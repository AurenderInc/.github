# Cursor 프로젝트 프롬프트 가이드

이 파일은 GitHub Organization Actions 리포지토리에서 Cursor를 사용할 때 참고할 수 있는 프롬프트 가이드입니다.

## 🎯 프로젝트 개요

이 리포지토리는 GitHub Organization에서 재사용 가능한 GitHub Actions 워크플로우를 관리하는 템플릿 리포지토리입니다.

## 📋 주요 프롬프트 예시

### 워크플로우 개발 시

```
GitHub Actions 워크플로우를 개발하려고 합니다. 
다음 요구사항을 만족하는 워크플로우를 작성해주세요:

[요구사항 작성]

기존 워크플로우는 .github/workflows/ 폴더에 있고,
문서는 doc/ 폴더에 있습니다.
```

### 문서 작성 시

```
워크플로우에 대한 상세한 문서를 작성해주세요.
다음 워크플로우 파일을 분석하고 doc/ 폴더에 Markdown 문서를 생성해주세요:

- 워크플로우 개요
- 트리거 조건
- 주요 기능
- 각 단계별 설명
- 필요한 시크릿 및 권한
- 사용 예시
```

### 기존 워크플로우 개선 시

```
기존 워크플로우를 개선하려고 합니다.
doc/ 폴더의 문서를 참고하여 다음 사항을 개선해주세요:

[개선 사항 작성]

워크플로우 파일과 문서를 모두 업데이트해야 합니다.
```

## 🔧 컨텍스트 제공 시 포함할 내용

### 프로젝트 구조
- `.github/workflows/` - 워크플로우 파일들
- `doc/` - 워크플로우 상세 문서
- `README.md` - 프로젝트 소개

### 주요 워크플로우
- **PR 리뷰**: AI 기반 코드 리뷰 및 변경사항 요약

### 개발 규칙
1. 모든 워크플로우는 문서화되어야 함
2. 문서는 `doc/` 폴더에 저장
3. `doc/index.md`에 새 워크플로우 추가
4. 시크릿 및 권한 명시
5. 사용 예시 포함

## 💡 자주 사용하는 프롬프트 패턴

### 1. 새 워크플로우 생성
```
새로운 GitHub Actions 워크플로우를 생성해주세요.
워크플로우는 [목적]을 수행해야 합니다.

요구사항:
- 트리거: [트리거 조건]
- 기능: [주요 기능]
- 시크릿: [필요한 시크릿]

워크플로우 파일과 doc/ 폴더에 상세 문서를 작성해주세요.
```

### 2. 기존 워크플로우 분석
```
이 워크플로우가 무엇을 하는지 분석해주세요.
각 단계가 어떤 역할을 하는지 설명해주세요.
```

### 3. 문서화
```
워크플로우 파일을 기반으로 상세한 Markdown 문서를 작성해주세요.
doc/ 폴더의 기존 문서 스타일을 참고하세요.
```

### 4. 버그 수정
```
워크플로우 실행 중 다음과 같은 오류가 발생했습니다:
[오류 내용]

관련 문서를 확인하고 수정 방안을 제시해주세요.
```

## 📌 중요한 사항

### 시크릿 관리
- 시크릿은 절대 코드에 하드코딩하지 않음
- 문서에 필요한 시크릿 명시
- GitHub Secrets 사용

### 권한 설정
- 최소 권한 원칙 적용
- 각 워크플로우마다 필요한 권한만 요청

### 문서화
- 모든 워크플로우는 상세히 문서화
- 사용 예시 포함
- 문제 해결 가이드 제공

### 재사용성
- Organization 템플릿으로 사용 가능
- 다른 리포지토리에서 참조 가능

## 🎨 문체 가이드

### 코드 작성
- 명확한 변수명 사용
- 주석 필수
- 에러 처리 포함

### 문서 작성
- 한글로 작성
- 이모지 활용하여 가독성 향상
- 단계별 명확한 설명
- 예시 코드 포함

## 🔄 워크플로우 개발 체크리스트

새 워크플로우를 개발할 때:

- [ ] 워크플로우 파일 작성
- [ ] 필요한 시크릿 정의
- [ ] 필요한 권한 정의
- [ ] 각 단계에 주석 추가
- [ ] 에러 처리 포함
- [ ] 문서 작성 (doc/)
- [ ] doc/index.md 업데이트
- [ ] README.md 업데이트 (필요시)
- [ ] 테스트
